# AI Piano Arranger —— 当前架构设计（2026-07-08）

> 本文件记录第二版的系统架构，其中有细节错误需要再次确定。

## 一、架构总览

```
Audio (song.mp3)
  │
  ├── beat_this ──────────→ beats.json          [轻量, < 2GB VRAM]
  │
  ├── MERT ──→ BeatSyncPool ──→ Linear(768→1024)
  │         (frozen)        (每 subbeat 一个)    ├→ melody_head(→512)
  │                                              └→ harmony_head(→512)
  │                                              ↑
  │                                        DistillationAdapter (可训练)
  │
  ├── piano.mid ──→ pretty_midi ──→ piano_beat.json
  │
  └── piano.mid ──→ Pop2PianoDataset ──→ piano_events.pkl  [Tokenizer]

特征 (512-dim melody + 512-dim harmony per subbeat)
  │
  ├── ConditionEncoder ──→ [B, L, 1, 512]      [frozen 或 LoRA]
  │     4-layer Transformer + bottleneck
  │
  ├── word_emb(generated tokens) ──→ [B, L, 512]   [frozen]
  ├── cls_emb(target/condition) ──→ [B, L, 512]     [frozen]
  │
  └── (相加) ──→ GPT-NeoX (8层) ──→ lm_head ──→ token logits
                      ↑
                   LoRA (rank=8, 所有线性层)
```

## 二、关键设计决策

| 决策                         | 结论                                                                      | 原因                                                      |
| -------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------- |
| **音频特征提取**                 | **MERT** (frozen) → BeatSyncPool → DistillationAdapter                  | Jukebox 5b/1b 均导致系统 OOM（16GB RAM 不够），Handcrafted 特征效果太差 |
| **MERT 是否训练**              | **冻结**，只训练 DistillationAdapter                                          | MERT 95MB 权重，冻结即可，特征已足够丰富                               |
| **DistillationAdapter 目标** | 拟合 SheetSage 的 `melody_last_hidden_state` + `harmony_last_hidden_state` | 让 PiCoGen 的 ConditionEncoder 和后续 Transformer 无需修改       |
| **DistillationAdapter 架构** | Linear(768→1024) → LayerNorm → GELU → Linear(1024→1024) → split(2×512)  | MLP 投影 + 双头分离 melody/harmony                            |
| **训练方式**                   | 用已存在的 sheetsage .npz 做蒸馏训练（MSE loss）                                    | 数据已经存在（0000 有完整 sheetsage 特征）                           |
| **Foundation Model**       | GPT-NeoX (8层 512-dim) **完全冻结**                                          | ADR-0002 要求 Foundation Model + Adapter                  |
| **Style Adapter**          | **LoRA** on GPT-NeoX 所有线性层                                              | rank=8, alpha=16, 约 500K 参数, 2MB 存储                     |
| **训练阶段**                   | **两阶段**：①特征提取（MERT 替代 Jukebox）→ ②LoRA 训练                                | 降低峰值显存                                                  |

## 三、DistillationAdapter 详细设计

### 架构

```python
class DistillationAdapter(nn.Module):
    def __init__(self):
        self.mert = MertModel.from_pretrained("m-a-p/MERT-v1-330M")  # frozen
        self.proj = nn.Sequential(
            nn.Linear(768, 1024),
            nn.LayerNorm(1024),
            nn.GELU(),
            nn.Dropout(0.1),
            nn.Linear(1024, 1024),
            nn.LayerNorm(1024),
            nn.GELU(),
            nn.Linear(1024, 1024),   # → [melody(512), harmony(512)]
        )

    def forward(self, audio_path, beat_times):
        # 1. MERT 推理 → [T, 768], 50Hz
        feats = self.mert(audio_path)

        # 2. Beat-sync pooling: 每 subbeat 内的 MERT 帧求均值
        pooled = []
        for subbeat_start, subbeat_end in zip(beat_times[:-1], beat_times[1:]):
            idx_s = int(subbeat_start * 50)   # 50Hz frame rate
            idx_e = int(subbeat_end * 50)
            pooled.append(feats[idx_s:idx_e].mean(dim=0))
        pooled = torch.stack(pooled)          # [num_subbeats, 768]

        # 3. Projection + split
        proj = self.proj(pooled)              # [num_subbeats, 2048]
        melody = proj[:, :1024]                # [num_subbeats, 1024]
        harmony = proj[:, 1024:]               # [num_subbeats, 1024]
        return melody, harmony                 # 都是 [num_subbeats, 512]
```

### 蒸馏训练

```
数据：
  * Input: 0000 的 song.mp3（音频）
  * Target: 0000 已有的 song_sheetsage.npz（melody+harmony, 512-dim）
  * Beat: 0000 的 song_beat.json

Loss:
  L = MSE(melody_pred, melody_gt) + MSE(harmony_pred, harmony_gt)

增强（扩展至 ~50K pairs）：
  * 随机裁剪 10s 片段
  * 时间拉伸 ±10% + 对应调整目标
  * 音高偏移 ±2 semitones + 对应调整目标

训练：
  * Optimizer: AdamW, lr=3e-4
  * Batch: 4 segments
  * Epochs: 200
  * 预期 loss: < 0.05 (MSE on normalized 512-dim)
```

## 四、两阶段管线（更新版）

### Stage 1: Feature Extraction（MERT 版本）

```
Input:  dataset/{id}/song.mp3 + piano.mid
Output: dataset/processed/{id}/*

步骤：
1. detect_beat(song)            → song_beat.json         [beat_this, <2GB VRAM]
2. extract_mert(song, beats)    → song_mert.npz           [MERT, ~1GB VRAM]
3. extract_beat_from_midi       → piano_beat.json         [pretty_midi, CPU]
4. align(song, piano)           → align_info.json         [fluidsynth, CPU]
5. tokenize(piano.mid)          → piano_events_*.pkl      [CPU]
```

**删除了 Jukebox/SheetSage 相关步骤。**

MERT 特征提取后不直接做蒸馏——蒸馏在 Stage 2 之前单独运行一次，生成拟合后的 512-dim 特征供训练使用。

### Stage 2: LoRA Adapter Training

```
Input:  dataset/processed/{id}/*
        已蒸馏的 .npz（MERT→512-dim melody+harmony）
Model:  PiCoGenDecoder (frozen) + LoRA (trainable)
Loss:   cross_entropy(logits, labels)     # 原始训练 loss
更新:   LoRA params only (~500K)
```

### 内存预算（更新版）

| 组件                      | GPU VRAM  | CPU RAM    |
| ----------------------- | --------- | ---------- |
| MERT (frozen, fp16)     | ~1.0 GB   | ~0.5 GB    |
| beat_this               | ~1.5 GB   | ~0.3 GB    |
| PiCoGenDecoder (frozen) | ~0.5 GB   | ~0.1 GB    |
| LoRA 参数 + optimizer     | ~0.1 GB   | ~0.01 GB   |
| Batch (B=4, L=1024)     | ~0.1 GB   | ~0.0 GB    |
| Activations             | ~3-4 GB   | ~0.0 GB    |
| **总计（训练）**              | **~6 GB** | **< 2 GB** |

**完全在 16GB RAM + 24GB VRAM 范围内安全运行。**
